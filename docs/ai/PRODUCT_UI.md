# 产品界面标准

新功能、改页面、补展示时，交付的是给品类/运营看的产品，不是给开发看的后台。

本文件是正本。Cursor 的 `.cursor/rules/product-ui.mdc` 只负责提醒读这里，换工具以本文件和 `AGENTS.md` 为准。

## 必须

- 一屏一个主操作。其余用次要按钮、文字按钮或「更多」。
- 用户看见中文：平台、状态、类型、结果。禁止把 `READY`、`xiaohongshu`、`FAILED` 直接铺在主界面。
- 先给结论再给明细。图表、状态、有效评论在前；任务 ID、原始报文、处理记录默认收起。
- 主列表默认展示有效评论，不要把重复条当成工作台正文。
- 文案说业务（清洗并分析、有效评论、正向），不说实现（Job、DTO、JSON、Worker）。
- 启用/停用必须能在列表上直接开关，不要只显示「是/否」再逼用户点编辑。

## 列表（所有表格必须同一套）

列顺序固定：

1. 主对象（项目名、文件名、评论、用途）
2. 关键属性（品牌、类型、匹配词）
3. 状态（开关或中文：完成 / 失败 / 成功）
4. 时间（有则放，北京时间）
5. 操作（文字按钮，最后一列）

样式：走全局表格样式，不要每个页面自造一套。表头弱、无竖线、只有行底部分割、行距一致。失败状态用醒目的错误色。本仓对应全局 `.el-table` 和失败用 `.status-text.is-bad`。

时间按北京时间（本仓用 `formatClock`）。说明用可读中文（本仓用 `friendlyMessage`），禁止把 Java 异常、类名、`octet-stream` 铺给用户。

空表必须写空状态文案，告诉下一步做什么。

## 禁止

- 同一区域并排多颗实心主按钮
- 用任务 ID、项目数字 ID 当用户要读的第一列
- 为了「功能做完了」把内部字段整表摊开
- 同一产品里有的列表用卡片套表、有的裸表、有的表头还是英文枚举
