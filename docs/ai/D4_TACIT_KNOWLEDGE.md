# D4 结构化隐性知识 — lumiinsight

代码周之前先记「以后一定会踩」的口径。有生产踩坑再追加。

## 1. 灯具方面词典（MVP 种子）

亮度、色温、外观、材质、安装、质量、售后、价格、物流、频闪、寿命、智能联动、遥控、防水、包装。

ABSA 输出的方面名必须落在词典或「其它」；禁止模型自由发明十几个近义词当新方面。对错集见 `eval/fixtures/golden-absa.jsonl`（含色温/安装/频闪/售后/亮度/外观/价格/物流），改词典或褒贬词后必须跑通。

## 2. 导入

- 同一「平台 + 评论ID」幂等；无评论ID 时用内容哈希。  
- 平台字段不统一：导入时映射到统一 Review，原始行进 JSON 备份列。商家后台导出列名（评价内容、宝贝标题等）要对上；无平台列时看文件名。  
- 失败行要能下载；状态要写清哪一列没认上、丢掉了哪几行，不能整文件静默丢弃。  
- 禁止把导入做成抓取。工作台「同步四个平台」写入内置评价，并把商品名换成项目主型号/竞品，不连开放平台。

## 3. 去水

先规则后模型。规则打的标签要给人看（广告、模板好评、过短）。不要第一周上图神经网络。

## 4. 报告幻觉

摘要模型只允许改写「统计结果 + 已检索原声」，不允许用训练知识补充竞品事实。超时或没配模型时回退规则稿，无证据句子仍不展示。

## 5. 公开仓

演示数据不要含真实用户手机号、内部未公开型号策略。样例用 `eval/fixtures/sample-reviews.csv`（工作台「下载样例」同一份），一次导入含本型号「演示吸顶灯」和竞品「星辉竞品灯」，能亮问原评、预警和竞品对照。改样例后跑 `python3 eval/fixtures/generate_sample.py`。

## 6. 演示口径

15 分钟路径：新建项目 → 同步四个平台 → 清洗并分析 → 看图和原评 → 打开报告 → 导出 PDF 或 PPT。失败只说业务话（分析服务没开、超时、未配模型已按词典），不念异常栈。卖点摘原评人话；竞品对照与页头用同一套有效评论。用量页只读。脚本见 `docs/演示说明.md`。
