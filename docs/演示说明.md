# 灯鉴 15 分钟演示

按这个顺序走，不必讲实现细节。浏览器打开 http://127.0.0.1:8282 。

## 准备（演示前 2 分钟）

1. 数据库、缓存已起来（独立 MySQL 3307、Redis 16379）。
2. 后台、分析进程、前端都已启动。
3. 用管理员账号登录。系统管理 → 模型配置：至少一家提供方有 Key，用途「方面情感」已选主模型。没配 Key 也能演示清洗和按词典的方面，但情感分析会降级。

## 脚本（约 15 分钟）

| 分钟 | 讲什么 | 操作 |
|------|--------|------|
| 0–1 | 工作台做什么 | 登录后停在「项目」。点右上「怎么走一遍」过一眼步骤。 |
| 1–3 | 建项目 | 新建项目，填品牌、主型号、品类。保存后点项目名进入。 |
| 3–5 | 导入 | 「下载样例」拿 CSV（或用仓库 `eval/fixtures/sample-reviews.csv`），点「选择文件导入」。等导入完成。 |
| 5–9 | 清洗并分析 | 点页头主按钮「清洗并分析」。顶部会提示正在处理，不要关页。完成后面板出现图表。 |
| 9–12 | 原评 | 点方面条或筛选方面，展开评论看正向/负向。主列表是有效评论。 |
| 12–14 | 报告 | 侧栏「报告」或页头「打开报告」。每条结论只有一个「查看原评」。可导出表格或文稿。 |
| 14–15 | 用量（可选） | 系统管理 → 用量。只读，不展示 Key 和评论文本。 |

## 卡顿或失败时怎么说

- 顶部红条「分析服务暂时连不上」：本机分析进程没开，先启动再点清洗并分析。
- 任务失败条可点「重试」。说明是中文，不要把异常原文念出来。
- 仍在跑：等一会儿或刷新项目页，不要连点主按钮。
- 没配模型：报告仍可从统计和原评生成；分析会按词典降级，用量页可能很少记录。
- 导出表格若仍报错：后台需要重启一次以加载导出修复。
