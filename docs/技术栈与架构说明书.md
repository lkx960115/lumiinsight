# 灯鉴 LumiInsight — 技术栈与架构说明书

**版本：** V0.1（空仓文档，无业务代码）  
**日期：** 2026-09-14  
**仓库：** `https://github.com/lkx960115/lumiinsight`（公开，独立于 ogsmProject）

AI 编码约束的精简版见 [`docs/ai/`](ai/AI_START_HERE.md)（D1–D6）。**同一事实以本文为对外权威**；六维文档只保留给 Agent 用的短表，并回指本章节。

---

## 1. 产品定位与非目标

**定位：** 面向灯具品牌的评论洞察平台：导入评论 → 去水 → 方面级情感（ABSA）→ 结论可溯源 → 自动报告。

**MVP 做：** 本地账号；项目；Excel 导入；清洗分析；单品报告与点选溯源；后台（用户、词典、**多模型配置**、审计）。

**MVP 不做：** 交易客服；未授权采集；四平台真爬取；智能问答；预警；多模态；Linux/K8s 生产部署。

## 3. 逻辑架构

```text
浏览器 (Vue3)
   │  JWT
   ▼
Spring Boot (apps/server)
   │  项目 / 导入 / 权限 / 任务编排 / 报告装配 / 模型配置
   ├─ MySQL 8          主数据、任务状态、模型配置密文
   ├─ Redis            会话、限流、队列辅助
   ├─ MinIO            导入文件、导出文件
   ├─ Qdrant           评论向量（W3）
   └─ HTTP
        ▼
FastAPI (apps/ai-worker)
        └─ 按「模型配置」调用各 LLM / Embedding（OpenAI 兼容为主）
```

**原则：** 浏览器不直连 Worker、不直连 Qdrant。Worker 不拥有账号权限模型。

## 8. LLM：后台配置、支持多种（已锁定）

**回答第 1 点：是。** 模型不写死在代码里。后台「模型配置」维护提供方与路由；Java 编排按 **用途（route）** 取配置，再交给 Worker 或 Java HTTP 客户端调用。

### 8.1 提供方（LlmProvider）

| 字段 | 说明 |
|------|------|
| name | 展示名，如「智谱」「DeepSeek」「自定义」 |
| protocol | 第一期只支持 `openai_compat` |
| baseUrl | 如智谱 `https://open.bigmodel.cn/api/paas/v4` |
| apiKeyCipher | Key **加密存储**，列表只显示后四位 |
| extraHeaders | 可选 JSON |
| enabled | 启停 |
| timeoutMs / maxRetry | 超时与重试 |

预置提供方（可改可关，不是代码常量）：智谱 GLM、DeepSeek、OpenAI、通义兼容端点、**自定义 Base URL**。

### 8.2 模型（LlmModel）

挂在提供方下：`modelCode`（厂商模型 ID）、上下文长度、是否支持 JSON Mode、输入/输出单价（用于成本页）、启用状态。

### 8.3 用途路由（LlmRoute）

同一系统可同时配多套模型：

| 用途 code | 典型 |
|-----------|------|
| `absa` | 方面抽取与情感 |
| `sentiment` | 整句情感（可与 ABSA 共用） |
| `report_summary` | 报告摘要（须基于统计+证据，禁止空手编造） |
| `embedding` | 向量 |
| `spam_classify` | 去水辅助（可先规则，模型可选） |

每条路由：主模型 + **备用模型**（主失败/超时则切备用）。未配置时才读本机环境变量兜底（`.env.example`），生产应以库内配置为准。

### 8.4 调用与安全

- 后台「测试连通」只发最短请求，结果写日志。  
- 日限额、token 记账到 `llm_usage`。  
- Key 不进 Git、不进前端接口明文、不进公开 README。  
- 换 Key、轮换提供方 **不改业务代码**。

### 8.5 与 Harness 的关系

模型再强，报告也不允许跳过证据校验。多模型只解决「用哪家脑子」；「必须引用原评」是 L6 约束，与提供方无关。

## 9. 流水线与 Harness

状态：`PENDING → IMPORTING → CLEANING → ANALYZING → INDEXING → REPORTING → READY / FAILED`。

| Harness 层 | MVP（三周） |
|------------|-------------|
| L1 信息边界 | 项目范围 + 方面词典 + 仅已入库评论 |
| L2 工具 | 统计、检索证据、填模板；无通用浏览器爬取工具 |
| L3 编排 | 上表状态机，LLM 不改顺序 |
| L4 状态 | 全落库，不靠聊天记忆 |
| L5 评估 | 三周内只做引用覆盖校验；黄金集 W2 末占位 |
| L6 恢复 | 重试、备用模型、无证据不出结论 |

开发侧：`AGENTS.md` + D1–D6 + 改前确认，对标 MCP 仓方法论，不引入额外 Harness 商业产品。

## 10. 本地运行（代码周生效）

1. 复制 `.env.example` → `.env`（切勿提交）。  
2. `docker compose up -d`。  
3. 启动 `apps/server`、`apps/ai-worker`、`apps/web`。  
4. 浏览器打开前端，用本地账号登录。  
5. 管理端配置至少一个 LLM 提供方后再跑分析。  

Linux 部署不在三周范围，届时仍以 compose 为默认形态。

---

## 11. 接口风格（约定）

- REST，JSON，统一包装 `{ code, message, data }`。  
- 写操作记审计日志。  
- 导入、分析、报告生成为异步任务，查询任务进度，禁止同步卡死 HTTP。
